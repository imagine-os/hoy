# HOY isolated Wompi test-class pilot (local candidate)
Tier T3. No live payment integration. Santa María software, credentials, checkout and payouts are outside scope.

Pinned HOY baseline: 0fcfa8d2ddb89a6d1397e7871178295c297fef1e, public v1.7.0. The server routes the pilot immediately after the existing team gate, only when an explicit pilot dependency is supplied; no production entry point constructs that dependency. No production build, Railway deploy or webhook is registered. Re-run with Node 24: `node --test scripts/wompi-sandbox/*.test.mjs`.

The pilot signs a single fictional class at 55,000 COP using a random per-subject quote reference and a fixed 15-minute checkout expiry. Origin and authorized test sign-in are checked; the existing HOY passphrase gate must come first. Require a secure verified identity allowlist for any hosted run, never a client-supplied subject. Only the authenticated sandbox provider API can verify a transaction's reference, amount, currency and status. Local SQLite records test results on the correct person and once per transaction; it does not activate a class, update Company OS finance or alter live data. Provider responses and hosted identities were fictional; an actual provider transaction and hosted role verification are still pending.

Before staging:
1. Require branch/tag protection and a verified dedicated test-only deploy identity in isolated HOY staging. Do not use the unrestricted shared GitHub environment for sandbox keys, or a production Wompi key at all. Keep signing, private and optional event secrets server-side. Put them directly into the approved secret recipient, not chat, code, logs, clipboard history, images or site assets.
2. Attach the pilot only to vetted staging operators on an HTTPS test origin. Require the existing test passphrase and the stand-alone test authority allowlist. Verify ownership of the test quote, cap retries, and give each successful or declined scenario a separately tracked fictional identity/attempt. Persist once-per-reference/id state and ensure that discarding the pilot cannot affect real class records.
3. Run one sandbox approved and one declined transaction via Wompi-hosted checkout only after the page visibly says MODO DE PRUEBAS, using documented test details and operator-controlled consent. Observe provider response, amount and local test receipt; retest unauthenticated and production routes disabled. If Wompi callbacks are added, separately verify signed delivery plus authoritative provider retrieval and protect shared merchant settings.
4. A separate production change and named production release require consent for the merchant actually displayed and paid, real-server replay/ownership and reconciliation, webhook/retry and refund plan, and verification that existing manual methods still work. No camera, card capture, merchant credential change, merchant payouts or live charges are part of this pilot.
