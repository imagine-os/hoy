rejected: (1) Fixing the wrap screen by screen (shorter labels, smaller font on S-03) — twelve screens use the tile and the EN `COP` prefix would have kept breaking the next one; the molecule is the one place. (2) A CSS-only `clamp()` / `cqw` font size — the needed size depends on the string length, which CSS cannot know; a `--chars` variable approximates glyph widths and misfires on tabular figures; measuring is exact and costs one layout read. (3) Only lowering the font — the frame case still stacked three ~100 px columns; the container query is the structural fix and makes the frame honest about what a phone shows. (4) Deleting or disabling the account client-side (what C-19 did) — a real deletion needs the auth user removed and the profile anonymised server-side, and disabling is what Apple explicitly rejects as "not deletion"; a request row with a tracked queue is honest today and is the contract the Supabase job implements later. (5) A `deleted_at` column on `users` instead of a table — the request has its own life (who asked, channel, reason, checklist, who closed it) and a public request has no user row at all. (6) Hard-deleting `payments` / `invoices` on request — Colombian accounting retention forbids it; anonymising the link is what the privacy policy already promised. (7) Reusing `consents` for marketing — that table is a document acceptance; the marketing switch is a `notification_prefs` row and 0008 already made that the contract. (8) A modal on the public page instead of a full W-09 route — Google Play needs a stable URL to declare. (9) A Google Form as the public deletion URL — it would leave the request outside the audit trail and the queue. (10) A `client` role or new permission for M-11 — the two roles that own personal data (admin, super_admin) are the route's `roles`; a new permission would have been a third place to keep in sync. (11) Using `M-10` for the queue — 0018 takes M-10 (Integraciones) in the parallel worktree.
