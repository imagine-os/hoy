# Hoy: fixes from Jas's 1 Nov acceptance walkthrough, administration and front desk (lane hoy-jas-1nov-admin)

Prompt intent: Jas walked the test environment (production build on Company OS) on 1 Nov. This lane builds the administration and front-desk items that had no open question (plan `drifting-popping-possum`, lane A): the Class schedule screen, a route-level error boundary, the payment settings save, the desk sale, the desk expense, Finance, the product master and the payments report.

Decision:
- ADM-01 / ADM-02, Class schedule: the screen read `/query` rows flat, but their fields sit under `data`, so names, times, teachers and rooms came out empty and Upcoming dates crashed (an empty `starts_at`). `flatRows` (`src/modules/staff/desk/useCos.ts`, reusing `fieldsOf` from `customerBalances.ts`) unwraps schedules, dates, coaches (the `person` include stays the embedded `{ id, name… }`) and rooms; `active` and `status` read again, so Cancel class is back on scheduled dates. The cancel note and its confirmation say a separately paid class is returned to the person's balance (`studio_cancel_returns_single: true`), not "contact them to reschedule". The email template's matching change is in the Company OS brief.
- Route-level error boundary: `withShell` wraps every page in `RouteErrorBoundary` (new organism, with its meta). A page that throws shows an error card with Retry and Home (the role's home) inside the shell, so the menu keeps working; opening another page starts clean. Retry reloads the page when its code failed to download (`lazyPages` keeps the failed import) and renders it again otherwise; Home on the role's own home renders it again.
- ADM-04, payment settings: in production the save is authorised from the session's `/me` roles (`heldRoles`: administrator or super_admin) instead of the person's `users` and `user_roles` rows, which a login without a person record doesn't have. Company OS still decides the write. The review build keeps its mock check. A refused save keeps its code (`saveFailureCode`) and the card shows the code's copy (new `payment_settings_*` lines in the code→copy table; Company OS codes such as `forbidden` already had theirs) instead of "the save was not confirmed", which stays for a save that really could not be confirmed.
- PRO-04, desk part: for an existing customer the desk sale reads their trial (`readTrialAssessment`, which is `assessLiveTrial` in production) and greys out the trial product with the reason ("ya usó su clase de prueba") when they hold a trial lot or a pending or approved trial payment. A walk-in, or a read that fails, greys nothing out. The server's `trial_used` stays the authority.
- REC-06: "Sell and check in" lists only today's classes that haven't started (`notStarted`, `deskSale.ts`), re-checked every 30 s. A class chosen before it started is no longer the choice (`chosenSession`): nothing is sent for it. The shared `useTodaySessions` hook is unchanged (the website uses it).
- FIN-01: Record expense has a "Pagado el / Paid on" date, today by default; the expense is paid and dated that day. The app no longer requires today: in production Company OS's rule (paid_on not after today, `invalid_date`) is the only limit, and its refusal is shown in words. The review build, which has no server, refuses a future day itself with the same copy.
- Finance: the Refunded card and the Refunded invoice filter chip are gone (no refunds is permanent, Q-16 of 22 Oct), with their copy.
- PRO-02, product master: the editor and its confirmation and errors sit together in one section above the list (only the message lines are live regions), and opening the editor, or Edit on another card while it is open, scrolls it into view. `product_period_overlap` and `invalid_date` are in `KNOWN_CODES` with es and en copy. "No price valid today" for a product created today with a price from today did not reproduce from the code (see the lane report); a test pins that such a row is in force.
- PAG-10: the payments report column reads "N.º de nota" / "Receipt no." (the number of the nota de compra).
- Integrated review round 1: the error boundary is no longer keyed by the path (that remounted every page on every path change and dropped its state, e.g. the cancel notice after `/app/booking/:id/change`, the Settings tabs, the schedule's day and week). It takes the path as `resetKey` and resets only a failure already on screen when the path changes. The desk sale says when the chosen check-in class has started ("choose another or sell without check-in", `startedChoice`).
- Integrated review round 2: the boundary's meta says public site routes show the card without the site header (no shell around them). The desk sale's "started" keeps a grace of 0; the check-in cut-off after the start (bookings `late_grace_minutes`) is an open question, as the app's booking policy doesn't carry it.

Alternative rejected:
- Filtering started classes inside `useTodaySessions`: the website's home uses the same hook.
- Checking the paid-on date in the browser (not after today): the plan keeps the server's rule as the only limit.
- Keeping the editor at the bottom of the product master and moving only the messages: the form itself was out of view after Add at the top.
