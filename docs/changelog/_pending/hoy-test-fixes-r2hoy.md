# Hoy test-fixes: integrated review round 2, Hoy fixes (lane r2hoy)

Prompt intent: the second integrated review of `hoy-test-fixes` found, on the Hoy side, 2 medium and 7 low findings, plus two contract items from the Company OS review: sign-up's `409 already_registered` has two meanings and Hoy took every one as success, and Hoy's `resource_overlap` copy offered a remedy that no longer works. The Company OS fix lane (r2co) split the code (`email_linked_to_other_login`) and added `details` to the timetable overlap refusal. In the same lane the owner answered two questions: L3 "Stop new classes only", and "every registered login is a customer" (no Join page).

Decision:
- Sign-up 409 (both reviews' M1): `classifySignup` no longer takes `409 already_registered` as done. The form re-reads `/me` (`signupHeld`). If the login now holds the customer role it goes on (a lost answer or a double tap); if not, it shows a conflict; if `/me` can't say, a retry line. `409 email_linked_to_other_login` (r2co contract) has its own es/en line ("contact the studio"), never success. `duplicate_person_user` has its own line. Every refusal has a copy key that fits the screen (`signupNoticeKey`), and the enrolment shows no raw code (L4). The code→copy table lists `already_registered`, `email_linked_to_other_login` and `duplicate_person_user`.
- Every registered login is a customer (owner 2026-11-01): the "Join as a customer" page (`JoinAsCustomer.tsx`) and its copy are gone. A signed-in login (staff or the super admin) without the customer role is enrolled automatically on its first customer-area page or purchase (`CustomerEnrolment.tsx`), through Company OS sign-up for an existing login, with nothing to fill in. The only step it may see is the studio's documents to accept once (`ConsentCheck`, the same step a new customer sees). `enrolmentBody` sends the login's name (when the tenant takes it) and the accepted documents, nothing else. Never in a preview frame or during view-as (`enrolsAsCustomer`, round 1's rule). Existing staff are enrolled on their first customer-area visit (the backfill).
- `resource_overlap` (r2co M2): the timetable editor shows `refusalText(failure)`. With the 1.6.0 details it names the class, its day and time, and a remedy that works: for another published row, another time or room (or, when replacing it, switch it off and start this row after its last class); for a class another row already made, start this row after that class, or cancel it only if nobody booked it. Malformed or oversized details fall back to the generic line, which no longer says "deactivate the other class first".
- Owner L3, "Stop new classes only": switching a timetable row off stops new classes. The classes it already made stay on the schedule and bookable, so neither the site nor the app marks them "No publicada" for that reason (this reverses r1hoy L7). Only a withdrawn class type does. `sessionUnavailableReason` and `sessionAdmissionAvailable` ignore the row's Published flag (a row that doesn't exist still closes the class). The editor hint and `timetable_deactivate_instead` copy say so: cancel a class to call it off.
- M2 (docs gate): the cap on Company OS `/me` is 2 MB (was 64 KB; the super admin's `/me` describes every entity with its fields). A test serves a 450 KB `/me`, and one of 3 MB is still refused.
- L2 (M-02): a timetable row's class type is only what it stores (`storedModalityCol`), never guessed from its title, so a draft titled "Pulso mañana" can't pass the publish rule while storing nothing. Classes keep their fallback.
- L5: `superAdminTab` decides for `PrivateDocsWatch` and `WireframeGate`. A `/me` that failed once (`error`) or is loading is not an answer, so the tab isn't reloaded and the skin stays. Signed out, or a settled session that isn't the super admin, drops them.
- L6: a docs pack (or a PDF) that lands after the drop is thrown away (a generation counter), and a load started after the drop doesn't join the dropped one.
- L7: `scripts/deploy-switches.mjs` warns when `PUBLIC_DOCUMENTS` is still set (like `SET_LIVE`), and both deploys run `--leftovers` before Apply infra, as `::warning::` annotations. Values are never printed.

Alternative rejected:
- L1 (timetable `If-Match`): declined. Company OS core doesn't honour `If-Match` on `PATCH`; tracked as Company OS tech-debt #72.
- Parsing the date out of the server's prose for `resource_overlap`: r2co added structured details instead.
- Keeping a Join page with a lighter form: the owner said there is no special way to become a customer.
- Writing the inferred class type on the first save (L2): it would store a guess.
