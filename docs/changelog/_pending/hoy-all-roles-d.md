# Hoy all roles: the Hub and read-only "view as" in production (lane D)

Prompt intent: super admins get the Hub in production and can see the studio as any of the other roles, read-only (P-03b, decision log "view-as read-only"), following Santa María's view-as pattern (`os/lib/auth.js`).
Decision: the hub module ships (`REVIEW_ONLY_MODULES` is `['docs']`) but production registers only a new super-admin page, `ProductionHubPage` (HUB-01, `/hub`, route roles `super_admin`, a "Hub" entry in the admin menu), from its own chunk: one "Ver como" card per role (the hub map's `HUB_ROLES` but super admin and public) and the hub map experiences production registers. The review hub (demo users, live preview frames, wireframe and dev toggles, persona switcher, its no-access page) stays review-only and is now a lazy chunk there too. The hub map's demo users moved to `src/hub/hubDemoUsers.ts` (review-only) so `hubMap.data.ts` carries no people and can ship; the published `hub-map.json` is unchanged. View-as (`src/auth/viewAs.ts`): the viewed role is kept in this tab's sessionStorage (`hoyos.viewAs`, wiped on sign-out with the other `hoyos.*` traces) and honoured only for a super admin (`isSuperAdminMe`; a planted value is removed for anyone else); the session's `role` is the viewed role with no super-admin bypass, `user` stays the real person, `viewAsPerson` is a sample person chosen by membership (`GET /admin/users` + `POST /query`: the first active coach for Teacher, the first member for Customer, the person holding the role key otherwise, never the viewer, never invented); `CompanyOSProvider.self()` aliases the session user to that person, so screens filtering by `user.id` show their records; switching remounts the tree. Read-only: while viewing as, `Transport.request` (and `raw` uploads) and `cosJson` refuse everything but `GET` and `POST /query` with `view_as_read_only` (Spanish and English copy in the code→copy table), before anything is sent; a stored view-as blocks writes even before `/me` answers (fail closed). A sticky banner (`ViewAsBanner`, D-02) shows "Viendo como <rol> · con los datos de <persona> · Solo lectura · Salir"; Exit goes back to `/hub`. `prune-production.mjs` now also fails the production build when a demo persona is in its JavaScript.
Alternative rejected: shipping the review `HubPage` with its demo parts folded out (it imports the persona switcher, live frames and demo users; a fold would leave their CSS and risk the H-10 guard); faking a sample person when none holds a role (the banner says there is none instead); per-screen read-only checks (one gate in the transport covers every write path).
