# Hoy all roles, lane G2: route connectivity models the live signed-out site

Prompt intent: lane F replaced the provider's built-in signed-out catalogue with live reads through the Hoy server's `public_site` identity; lane G's check still modelled the old site, so on the merged branch it failed on stale entries and its signed-out hostile checks passed only by short-circuit.
Decision: `scripts/test-route-connectivity.mjs` reads the signed-out model from the code: `PUBLIC_TABLES` and the `list()`/`get()` guards in `CompanyOSProvider.ts`, `PUBLIC_ENTITIES` in `server/app.mjs`. A signed-out page may read static tables and the live set (PUBLIC_TABLES whose entity the server forwards); any other signed-out read is `signed_out <table> (empty)`, any signed-out write `signed_out <table> (write)`. It fails closed when a guard changes shape or a PUBLIC_TABLES table is not forwarded. Hostile checks no longer short-circuit; new ones: a read outside the live set, the settings row and a write fail, the live tables pass (list and get), and the same pages signed in do not. Lane F's seven PENDING entries and the stale BY_DESIGN went; what remains is OPEN (`tenants` settings row and `bookings` mat map on `/site/*`, closes: lane H2) or BY_DESIGN (the settings save no visitor calls, with its new reason). `docs/route-connectivity.md` has a *Signed-out pages* section, the findings and the refreshed `/site/*` inventory.
Alternative rejected: dropping signed-out judging (the server decides): an empty read would ship silently, which is what the check exists to catch; a hard-coded live-table list in the check: a second copy that drifts from the provider and server.
Files: `scripts/test-route-connectivity.mjs`, `docs/route-connectivity.md`.
