# Hoy test-hoy fixes: purchases for any signed-in person, plus deploy fixes (lane Y2)

Date: 2026-11-01. Codes: P-01, P-02 (schedule CTA), C-04, C-06, C-08, A-02, A-03, S-* / M-* (staff shells).

Prompt intent: on test-hoy, Book (Plans) and Give a gift landed on the admin dashboard for anyone signed in who isn't a pure customer. Owner's rule (2026-11-01): an Administration person who is also a customer, with one email, goes straight into booking and payment like any customer. Also: the frontend deploy failed at "Apply infra" (`COMPANY_OS_READ_TOKEN` not declared in `.railway/railway.ts`), and an expired Clerk session made the signed-out website's reads 401.

Decision:
- The session carries every role the login holds (`roles`, from `/me`, primary first; `rolesFromMe`; while viewing as, only the viewed role). The customer area `/app` opens for any login holding the customer role, whatever its primary role: `RequireRole` renders the customer pages with the session's role as `customer` (same person), so the customer shell, its menu and the customer-only branches behave as for any customer. The staff menu gains "Mis clases / My classes" (to `/app`) for such a login; the customer shell shows "Volver a <rol>" back to the primary role's home.
- The website's Book (Plans), Give a gift and the schedule's "Continue booking" go through `purchaseEntry` (`src/auth/purchaseEntry.ts`): signed out → sign-in keeping the return (as before); signed in, any role → straight to the purchase or booking page.
- A signed-in studio login that isn't a customer yet sees "Únete como cliente / Join as a customer" on a customer page (`src/auth/JoinAsCustomer.tsx`, the studio sign-up form starting from its name). Company OS now adds the Customer role and the member facet to the same login and person (`POST /t/:t/signup`, ADR 0038 amendment 2026-11-01, Company OS lane Y2); the page then opens as a customer. Never while viewing as.
- `homeFor` (where sign-in lands) follows an `/app` return for a login holding the customer role, and a purchase or booking return (the customer allowlist) for any studio login; other `/app` returns still send staff home, and a staff return is still judged by the primary role's matrix.
- Hoy server: an invalid or expired session on a website read (`POST /query` on a public entity, `GET /api/<public entity>`) is answered with the server's read identity and `X-Hoy-Session: stale`; every other route still answers 401. The transport, seeing that header after sending a token, asks Clerk for a fresh token once, then keeps the public answer and tells the session to re-check.
- `.railway/railway.ts` declares `COMPANY_OS_READ_TOKEN: preserve()`. Both deploy summaries print the go-live switches through `scripts/deploy-switches.mjs`: SITE_LIVE (true / false / not set / invalid), SITE_LIVE_AT, whether the read token is present (never its value), and a warning when a `SET_LIVE` variable exists.

Alternative rejected: making every role check use every held role (staff areas too): wider than the owner asked and the staff screens decide with the primary role (queued). Keeping the no-access page for staff on customer pages and asking Administration to grant the Customer role by hand (the owner wants one email and no detour). Answering an expired session on a public read with 401 so the browser refreshes (a dead session would keep the website broken).

Changed on purpose: `test-hoy-server.mjs` "the visitor's own headers never become the identity" (a refused bearer on a public read now gets the public answer, still never forwarded); `test-auth-production-ui.mjs` front desk on `/app` is offered Join instead of no-access.

company-os.json now requires >=1.7.1: the first Company OS release after v1.7.0 carries the sign-up amendment (E9: API before frontend).

Owner steps: rename the Railway variable `SET_LIVE` to `SITE_LIVE` (the summary flags it), then Deploy. Company OS must be released with the sign-up amendment before "Join as a customer" works on test-hoy (with an older API it answers `already_registered`, which the form treats as done and nothing changes).
