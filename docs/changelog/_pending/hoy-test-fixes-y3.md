# Hoy test-fixes: Justin's Hub in production (lane Y3)

Prompt intent: after the owner's first walk of test-hoy (2026-11-01), the Hub is Justin's Hub, unchanged in look and features, hooked to real data: "Entrar como {first name}" for the person holding each role, live read-only previews, Report a problem, the Construction & testing band (manual, source documents, docs, kanban; super admin only) and the wireframe toggle (session-only). Plan `cryptic-swimming-whale`, lane Y3.
Decision: production `/hub` renders the review build's `HubPage` (HUB-01, route roles `super_admin`, `surface: 'public'`, `layout: 'auto'`: its own full page, no staff shell); lane D's `ProductionHubPage` is retired. The page differs only where data is real, chosen by the folded `PRODUCTION_BUILD` so no demo user ships: cards and the persona dropdown name the real person of each role, the one view-as samples (`src/modules/hub/hubPeople.ts` reuses `loadViewAsSample` with one cached `GET /admin/users`); choosing one starts read-only view-as (`setViewAs`) and opens the role's page; the super admin's and public cards just navigate; a card or tool whose route production does not register yet shows "Planeada" and is not entered. Live previews (in view, at most 3, never under automation) run in frames under their own `?as=` through a production frame mode (`src/app/productionFrame.ts`, the review build's `frameSession` pattern split from its demo users into `frameMode.ts`): the frame's view-as, language, theme, skin and every other `hoyos.*` key are its own and never touch the parent tab; every frame is read-only (a frame with no viewable role keeps a sentinel the session ignores and the transport's fail-closed check honours; a same-origin `/api/` write through `fetch` is refused unsent) and hides the view-as banner; clicks never reach a preview. `?as=` is ignored outside a frame, and in a frame it counts only for a real super admin (ProductionSession's existing rule). Report a problem creates a `problem_report` `form_submission` (Company OS forms module, recipe lane Y1) through the runtime with an Idempotency-Key, refusals in staff words. The manual, the source documents, the docs browser and the kanban ship for the super admin only: `REVIEW_ONLY_MODULES` is empty, globs over `docs/` keep their markdown and images but never `docs/screenshots/`, demo persona ids, names and e-mails are redacted from the bundled docs (`[demo]`), `public/source/` ships, and the routes entered `LAUNCH_ROUTES` through the connectivity check (green: in production the manual is read-only, its LMS tables have no Company OS entity, so `manualData.ts` reads none of them and every LMS write says "not available yet"; a chapter's stats block counts active packs from the ledger). The wireframe skin is the super admin's for this tab (sessionStorage `hoyos.skin`, removed with the other `hoyos.*` traces on sign-out) and `WireframeGate` resets it for anyone else; the review build keeps it in the remembered theme. `src/app/frameSession.ts` joins the review-only data the production build refuses to ship.
Alternative rejected: keeping lane D's simplified page beside Justin's (the owner asked for Justin's); a fake sample person per card (the session's own pick is shown, so the name on the button is the person whose data appears); naming a person in the dropdown that view-as cannot sample (choosing a specific person needs a sample override in `src/auth`, queued); shipping the manual's LMS writes against tables with no Company OS adapter (they would refuse `not_in_launch` after the fact); excluding docs files that name demo users (they would lose their content; redaction keeps it).
