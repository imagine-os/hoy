# Hoy test-fixes: the Hub's docs behind a server gate (lane Y6)

Prompt intent: lane Y3 shipped the Hub's Construction & testing band (manual, source documents, docs and changelog, kanban) for the super admin, but only as a route guard: the text sat in the public JavaScript and the PDFs were public files under `/source/`, so anyone could fetch them signed out (Y3 review finding 1, HIGH). Owner decision 2026-11-01: "Gate on the server first": the Hoy server serves the docs, manual, kanban and source files only to a signed-in super admin.
Decision: the production build bundles nothing from `docs/` (every `import.meta.glob` over it is `{}`, a direct import is empty, and the build fails if a `docs/` module is rendered into a chunk) and `public/source/` is pruned from `dist/`. The build writes a private pack beside the public one, `<dist>-private/` (`vite.config.ts` `writePrivateDocsPack`): `docs.json` with every markdown body and its docmeta index (demo personas redacted as before), the docs images as data URLs and the source-document index with its covers, plus `source/` with the PDFs. `server/make-bundle.mjs` ships it as `site-private/` and scans it for secrets too; the static server never serves it. `server/docsGate.mjs` answers `GET /private-docs/docs.json` and `/private-docs/source/<file>` only when the bearer is a valid Clerk session (the existing `clerk.mjs` check) and Company OS `GET /t/<tenant>/me`, asked with that same token, says the person works as Super admin (`isSuperAdmin: true` without `administrator`: an AD-04 Administration login also holds super_admin, the same rule as `isSuperAdminMe`); cookies and client headers are never read and Y2's stale-session fallback never applies. Signed out or a bad token is 401, any other role 403, an unlisted or traversal path 404 (only after the super admin check), all `Cache-Control: private, no-store`, `Vary: Authorization`. Files are looked up in a list made at start, never by resolving the request path. In the app, `PrivateDocsReady` loads the pack with the session token (`getSessionToken`, the only token path) before the docs, manual or kanban chunk first evaluates (`privateDocs.ts`); `docsIndex.ts` and `sources.ts` read it in production; a source PDF is fetched through the gate as a `blob:` URL (`SourceDocEmbed`). The Hub's chapter count is a build-time number. Review round: a sign-out (or any change away from the signed-in super admin) revokes the PDF links and reloads the tab, so the pack never outlives the session in memory (`PrivateDocsWatch`); a 401 from the gate retries once with a refreshed token and then re-checks the session; the pack is pre-compressed at build time (`docs.json.gz`); the build also fails on any emitted asset from `docs/` or `public/source/`; a review build removes a stale private pack. The review build is otherwise unchanged.
Alternative rejected: shipping as is, public by URL (owner chose the gate); keeping the docs routes and `source/` out of the release until a gate exists (the fallback, not needed: the gate is green); a cookie-based gate (the server reads no cookies, so there is no CSRF surface); one gated request per markdown body (search reads every chapter: one `/me` call per file); caching `/me` answers on the server (a revoked super admin would keep access for the cache's life).
