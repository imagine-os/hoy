# Hoy all roles: every role signs in to its own home (lane C)

Prompt intent: the owner reversed the reduced launch scope (P-03b): every one of Hoy's 11 roles works at launch, super admin included; memberships are class packs (R-05).
Decision: one role-key table (`ROLE_KEYS`, `src/auth/companyOsIdentity.ts`) maps every Company OS key to a HoyOS role in a documented primary order (Administration, Super admin, Coordinator, Finance, Front desk, Marketing, Maintenance, Developer, Teacher, Customer); Administration keeps its role although it holds the tenant `super_admin` membership (AD-04), so Super admin is a `super_admin` login without `administrator`. Super admin is a real production session role (`isSuperAdmin` from `/me`). The role matrix states access for all 11 roles (launch columns unchanged; the new roles follow their route roles until Jas confirms, A-02). `/teach`, `/admin/content` and `/dev` are launch homes (only the `/dev` page of the dev module ships). The team panel grants and changes every staff role; only a super admin offers Super admin. The customer home's plan card shows the active pack and the admin dashboard counts customers with an active pack (credits), with the review build's membership rows kept. A payment's `paid_at` is its `approved_at`.
Alternative rejected: treating every `isSuperAdmin` login as Super admin (every Administration login holds `super_admin` under AD-04, so the Administration role would never be reached); a production-only home table (several screens read `ROLE_HOME`).
