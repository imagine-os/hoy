# Hoy test-hoy fixes, lane Y1: the schedule's class type, room and timetable seed

Prompt intent: the owner's first walk of test-hoy (2026-11-01) found 14 placeholder classes ("Morning flow", "Evening stretch") next to the seeded ones, with no class type or teacher; the booking drawer saying a bare "Unavailable"; every class in "Main studio"; and a stray " · " on a card without a teacher (plan cryptic-swimming-whale, lane Y1).
Decision:
- Company OS (same lane): the recipe holds no placeholder timetable; Hoy's class types are the tenant field `modality` on `schedule` and `occurrence` (the class type's slug); a room holds one class at a time (`enforce_no_overlap`).
- C-02, P-schedule, C-03: a class's type is its own `modality` (a class added by hand), else its schedule's (the class query includes `schedule` as `schedule_row` with `modality`; a get by id goes through the same query), else its title. A class with none is "Aún no abre reservas / Not open for booking yet" (`no_class_type`) on the calendar tile, in the site's booking drawer and on the class detail, in line with admission.
- P-schedule: the drawer names the class's room from the rooms table (public), never the fixed "Sala principal / Main studio" string (removed).
- ClassCard (D-02): the meta line joins only the non-empty parts (`classCardMeta`); the library usage shows a card without a teacher.
- M-02: the timetable row's class type is required.
- Seed (`scripts/seed-companyos.ts`): the sample's timetable as `schedule` rows (coach, room, class type, length, mats), every class linked to its row, the class type checked against the recipe's options; Company OS's test setup goes live after the seed, so generation continues it.
Alternative rejected: joining the schedule's type in each page (admission, the class detail and the staff screens read `modality_id` straight from the class); copying the type onto every seeded class (a generated class would still have none); a seed without schedules (generation would make a second class next to each seeded one).
