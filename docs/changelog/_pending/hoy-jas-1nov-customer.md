# Hoy, Jas's 1 Nov walkthrough: customer and identity fixes (lane B of hoy-jas-1nov)

Prompt intent: Jas walked the test environment on 1 Nov and logged about 60 rows. Lane B takes the customer and identity rows that have no open question (plan `drifting-popping-possum`, owner answers of 2026-11-02). The main one is the root cause of the "no profile" reports: email-code logins have no name, so the automatic enrolment sent none, and Company OS refused the sign-up 400 `validation` (a person needs a name). The app then let the login carry on with no person.

Decision:
- **Enrolment name (root cause 1).** When the login has no usable name (`usableLoginName`: 2+ characters, no "@", not the email that `ProductionSession` falls back to), the enrolment and consent step shows a required "Tu nombre / Your name" field (`enrolmentNameError`: 2+ characters, no "@"; the input and the body are cut at `SIGNUP_FORM_LIMITS.name`). The sign-up sends the name. A 400 from Company OS brings the step back, and the field says to check the name. Company OS stays strict. A named login is never asked and sends its own name (unchanged). The name is sent and shown as text.
- **C-01d (owner 2026-11-02, replacing C-01c's "book anyway").** "Continue for now" now defers the consent (`deferConsent`) instead of settling it. The customer area opens for existing bookings, the balance and the account. Every new booking or purchase entry shows "Registra tu consentimiento para reservar / Record your consent to book", with Retry, and starts nothing: app checkout, Plans, Passes, Buy more, gift purchase, and the website schedule's Book button. Retry forgets the deferral (`retryConsent`), so the page's guard reads `GET /signup` again and shows the consent step. Once it is recorded, the page opens. The bounded read and the fail-open timeouts are unchanged (IN-155): a failed or slow read still opens everything, because nothing says a consent is missing. Display only: server enforcement stays Company OS tech-debt #74.
- **Lane review fixes.**
  - The product payment page (`/app/pay/product/:key`, reached by a link or history) also shows the consent hold and renders no form, so no payment or receipt is created. Paying an existing held booking (`/app/pay/booking/:id`) stays open.
  - A login that deferred keeps its hold when a later `GET /signup` can't tell (failed, timed out, an older Company OS). Only a registered answer, sign-up closed, or a recorded consent lift it (`passAfterRead`). A login that never deferred still fails open (IN-155).
  - Only a 400 `validation` points at the name field. Other refusals (`duplicate_person_user`…) keep their own notice and "Continue for now".
  - The name is asked only when the tenant takes `name` at sign-up. Whether the person row already has a name isn't known to the step (`GET /signup` and `/me` don't say), so a nameless login is asked, and Company OS fills only what the person lacks.
- **PAG-03.** A hold whose time ran out (`awaitingRelease`) reads "Pago liberado / Payment released", never "pending". The booking page re-reads the booking and the class every 10 s, for 6 minutes at most (the server releases lazily or every 5 minutes), so the place count refreshes once Company OS sets `cancel_reason: hold_expired`.
- **PRO-04, customer part.** Checkout, the home cards, Passes and the class detail's button label use `trialOffered` (`ent.trial`, the live assessment: a trial lot, or a pending or approved trial payment) instead of `trialUsed`. Package holders still see the trial (R-14 is open). The server's `trial_used` still decides.
- **PRO-05.** App checkout, the signed-in Plans page and "Buy more" on the balance show the affiliate-only pack (the pricing item with an `audience`) only when the member facet's `price_audience` is `affiliate` (`useAffiliate`, read the same way as the transfer payment). While the facet is unread, or the read fails, the pack is hidden. The review build and the public site are unchanged (open question). The server still refuses `audience_not_allowed`.
- **PRO-06.** The home card and the balance list each live lot (`liveLots`) with its source (`lot_source`: bought pack, trial, gift, courtesy, studio courtesy, voucher; anything else reads as "Clases") and its expiry, or "sin vencimiento / no expiry". This replaces the single "your pack" line. New molecule `LotList`, with its meta.
- **WEB-03.** When there is a session, the website schedule drawer uses its own title and body (`drawerCopy`: "Reserva esta clase / Book this class").
- **RES-01.** `useCustomerRows` keeps the rows on screen while the same read refetches, so the calendar no longer unmounts on the 20 s poll. `SessionCalendar` `syncUrl` keeps the day and view in the query (`day`, `cv`; replaced, not pushed), so Back from a class returns to the same day. `cv` is used because the schedule sends `?view=week` to the week route. The week grid lost its fixed minimum width, which cut Sunday off at 1024 px.
- **RES-02.** The greeting uses the first name on the person's own person row, then the login's name, never the email (`greetingName`; "Hola / Hi" without a name). The fixed demo announcement ("this Saturday the 10:00 class is outdoors") shows only in the review build.
- Integrated review round 1: while the consent hold is on, Buy more's pack rows are disabled buttons (`aria-disabled`, dimmed; new `disabled` state on `PriceRow`), not only inert.
- C-01d, owner decisions of 3 Nov: a move counts as a new booking, so while the consent is held the change sheet's move mode shows the hold notice and offers no class (`ServerChangeSheet`); cancelling an existing booking stays allowed, and the review build's reschedule is unchanged. "Continue for now" now lasts for the browser session: the deferred login ids (nothing else) sit in `sessionStorage` under `hoyos.consent.deferred`, every access guarded with a memory fallback, so a reload or a new tab keeps the hold (a "not registered" read keeps it too, except after the notice's Retry) until a registered answer, sign-up closed or `settleConsent`, which clear the entry; sign-out clears it (`clearConsentOnSignOut`, IN-145).

Alternative rejected:
- Sending the email's local part as the name, or a placeholder name: Company OS would hold a made-up name for the person. Rejected for asking.
- Letting Company OS accept a nameless sign-up: the owner chose to keep it strict (asking for the name on screen).
- Keeping "Continue for now" as a full pass, which is C-01c: the owner replaced it with C-01d.
- Blocking the whole customer area until the consent is recorded: it would lock a paying customer out of their bookings. Rejected, as in r2hoy2.
- Showing the affiliate pack and letting the server refuse it: Jas reported it as a bug (PRO-05).
- Hiding the trial from package holders: that is R-14, still open.
