# Hoy all roles, lane H1: the mock-only launch flows run on Company OS

Prompt intent: lane G's route-connectivity check found launch screens whose flows only ran on the review build's MockProvider (`data.name !== 'mock'` → `*_disconnected`) or read and wrote tables with no adapter; the owner decided to close them in Wave 1 (lane H) rather than cut them. H1 is the Hoy frontend half (screens and their data modules); H2 owns the recipe and adapters, H3 the credits change.
Decision: each flow gets a production path chosen once per build (`PRODUCTION_BUILD ? live : review`), so the review build keeps its fictional simulation unchanged and production never loads it.
- C-19/C-21 notification preferences: comms `notification_pref` (no row = enabled), one keyed `/batch` per change; production channels whatsapp, email and in_app (the review build's push is hidden).
- C-19 profile: name, date of birth, emergency contact and phone go to the person in one keyed `/batch` and are read back; a value the backend did not keep is reported (`profile_unconfirmed`), never a silent "saved". The email-change preview becomes copy: the studio changes a login email (people: `email_change_not_allowed`). The photo upload and WhatsApp "verify" wrote fields Company OS does not keep, so they are review only.
- C-26 account: the export is built from the tables a member reads; the deletion request is a keyed `deletion_requests` insert that lane H2's adapter sends as the forms module's `privacy_request` submission ("request sent"; cancelling is with the studio); production copy replaces the FICTIONAL notices. The marketing switch writes `notification_pref` marketing rows and works the opt-in out from them.
- The trial check (8 customer routes) reads the person's own lots (the trial product's lot, or `lot_source` once H2 adds it) and pending or approved trial payments; the server's `trial_used` stays final.
- C-07b "buy more" lists the product master's live prices and opens the payment page, like C-06; `recordPayment` refuses `checkout_server_only` under `SERVER_RULES`; the browser quote is review only by build flag.
- M-08 payment instructions save through the settings adapter in one keyed `/batch`; a retry after a lost answer succeeds instead of `payment_settings_stale`.
- M-09 finance labels a sale without a product by `payment.concept`; the `special_charges` read is review only.
- C-08/C-10 the class the studio cancelled: `ownStudioReturn.ts` reads the person's `cancel_return` ledger entry for the booking (credits `studio_cancel`; lane H3's one-class lot for a paid single class). The admin cancel was already a status update.
- S-03 Teacher home: classes, today's rosters (inline, names and arrivals) and the week read live; specials, substitute requests, the payroll estimate and the rating say "available later" (Waves 2–4). M-02 content editor: reads live, every save is refused `content_later` with copy before anything is sent (Wave 3).
- AD-07 customer list reads `/query` rows as `{ id, data }` (`customerListRows`): balances, packs and expiries were empty.
- Code→copy: `email_change_not_allowed`, `notification_pref_duplicate`, `content_later`, `checkout_server_only` (es, en).
- Route check: the OPEN entries H1 closed are deleted, the Teacher and Marketing homes' entries name their wave, a stale DYNAMIC entry went, and `docs/route-connectivity.md`'s findings and inventory are regenerated (`--report`). `CLAUDE.md` lists all 11 role keys.
Alternative rejected: hiding the flows in production (cutting the routes) — the owner chose to connect them; a BY_DESIGN entry for the email change — the preview is chosen out of the production build, so the entry would be unused and the check fails on unused entries; re-implementing the "active pack blocks a trial" rule in production — the backend lacks it (raised, not re-implemented).
