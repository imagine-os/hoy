# Hoy all roles, lane E: the activity log on Company OS, and sign-up proven on test-hoy

Prompt intent: `/admin/activity` was a launch route that was always empty in production (it read `audit_log`, which the connector maps to a sink), and sign-up had only been checked against a fake Company OS (decision log P-03b; INBOX IN-107).
Decision: M-07 reads the tenant's Company OS audit trail, `GET /t/:t/audit`, through a small module (`src/data/companyos/audit.ts`): the range is sent as `since`, every page of 500 is read (from one millisecond past the last row, seen ids dropped, so rows sharing a timestamp are not skipped) up to 5 000 rows with a notice beyond that, and names come from `GET /members`. Only the tenant Super Admin may read it (Administration, AD-04); a refusal shows its copy (`forbidden` with a Super Admin line, `invalid_query` new in the code→copy table, the service line with a retry), never "no activity". The review build keeps the mock's `audit_log`. `scripts/test-auth-real-clerk.mjs --real-api` runs the real-Clerk sign-up against the deployed test site and its real Company OS, checks the new login is a `member` with a `self_signup` record, then removes its Company OS records through the API (as a test-hoy Administration login, a short Clerk Backend API session) and the Clerk user; a by-hand workflow job (`real_signup`) runs it.
Alternative rejected: mapping `audit_log` to the audit route inside `CompanyOSProvider` (shared with two other lanes, and the table's write side stays a sink); removing the QA user's records with the platform key (the API is private; the only public way in is the Hoy server with a Clerk session).
Files: `src/data/companyos/audit.ts`, `src/data/companyos/refusals.ts` (one line), `src/modules/admin/ActivityPage.tsx`, `src/modules/admin/strings.ts`, `scripts/test-admin-activity.mjs`, `scripts/test-admin-activity-ui.mjs`, `scripts/lib/real-signup.mjs`, `scripts/test-real-signup.mjs`, `scripts/test-auth-real-clerk.mjs`, `.github/workflows/auth-checks.yml`. Page code M-07.
