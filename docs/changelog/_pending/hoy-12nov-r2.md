# Hoy 12 Nov, review round 2 fixes: titles after hydration, check-in follows the clock

Prompt intent: the second integrated review found that the browser replaced the server's page titles and JSON-LD once the app loaded (the first thing search engines and tabs would show), and that the check-in screen stayed on the first class it showed all day.
Decision: one table of public page titles and descriptions (`server/pageMeta.mjs`) is written by the server and kept by the browser (`src/modules/website/pageMeta.ts`); in the production build `RouteTitle` uses it for the website's routes, so `/clases/fuego` stays "Fuego: Enciende tu energía · HOY Human Club" instead of "Sitio · Clase · HOY", and leaves the root entry's title alone. The website's JSON-LD hook leaves the server's richer `HealthClub` element alone (it only makes and removes its own, marked `data-client`, in the review build). Check-in: with nothing chosen the screen follows the live or next class again; a class staff choose (a tap or `?session=`) stays, and once it has ended and a later one is live or next a "Ir a la siguiente clase" button returns to following the clock (`src/modules/staff/checkinSelection.ts`). The decline hint reads "Si rechazas, la persona verá este motivo."
Alternative rejected: writing the shown class into the address (round 1): a tablet opened at 06:30 would stay on the 07:00 class all day.
