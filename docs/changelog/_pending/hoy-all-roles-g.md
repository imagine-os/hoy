# Hoy all roles, lane G: every launch route is connected (route connectivity check)

Prompt intent: prove mechanically, page by page, that every production route reads and writes through a working Company OS adapter (Hoy all-roles plan, Wave 1 lane G), and audit the launch routes and the cut routes Waves 2–4 add back.
Decision: `scripts/test-route-connectivity.mjs` bundles each launch route's page as the production build sees it (esbuild, `PRODUCTION_BUILD` folded, tree-shaken, dynamic imports followed) and judges every table, provider method and `request()` path it reaches against `src/data/companyos/mapping.ts` and `CompanyOSProvider`; it fails on sink, unknown and read-only tables, stub and missing methods, mock-only flows, `not_in_launch` throws and empty signed-out reads, with hostile synthetic pages. Known findings sit in `PENDING` (Wave 1 lanes C, E, F) or `OPEN` (no lane yet), both failing when stale; `BY_DESIGN` holds the seven unconnected-on-purpose uses. It runs in the auth-checks workflow. Rule: a route enters `LAUNCH_ROUTES` only when the check is green for it (`CLAUDE.md`, `docs/route-connectivity.md`). The audit and the Wave 5 test-hoy access walk are described in `docs/route-connectivity.md`.
Alternative rejected: a regex walk over the import graph (counts review-only branches and every page of a barrel, so it reports pages the production build never runs); a browser walk only (needs every role's data and catches a gap only where the seed happens to have rows; it is Wave 5's job on test-hoy).
Files: `scripts/test-route-connectivity.mjs`, `docs/route-connectivity.md`, `.github/workflows/auth-checks.yml`, `CLAUDE.md`.
