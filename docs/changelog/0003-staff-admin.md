S-04 reads products only from src/tenant/pricing.ts and IVA from M-08 tax settings (prices include IVA by default, matching the seeded invoices), creates users + profiles + user_roles + consents + payments + invoices + memberships/credits + optional check-in, and shows a printable Receipt; the Wompi link leaves the payment pending. Teacher app: attendance window T−15m…T+2h with coordinator override, notes and substitution requests as audit_log rows (visible in M-07), payroll = completed sessions × teachers.rate_per_class flagged as a placeholder. Admin: M-02 is a field-config-driven DataTable + Drawer CMS over class_templates/teachers/modalities/rooms with publish toggles (active) and a preview pane; M-04 keeps bodies as JSON {es,en,cta} inside email_templates.body_mjml, versions = the template's audit rows (rollback restores before), test send = message_log with payload.test; M-05 blocks enabling an automation whose wa_template is not Meta-approved and reads quiet hours from M-08; M-06 computes segments and churn risk from the member's own cadence, stores staff notes as audit_log member.note and logs member.view; M-07 is read-only over audit_log with CSV export; M-08 stores every parameter in tenants.settings through useSettings() with defaults from tenant.ts; M-09 (new code) groups approved payments by plan and method with BarList, lists refunds (payments.refund permission) and invoices with the DIAN CUFE column. Seven new components ship with metas; realtime uses the provider's subscribe() through useTable so a Supabase provider lights it up unchanged.
rejected: New tables for notes, versions, payroll runs or settings (the 29 existing tables cover it: notes and versions in audit_log, settings in tenants.settings; avoids touching the shared schema in a parallel build). Editing seeds to add the eleven email templates and nine automations (shared file; instead a "create standard set" action inserts them through the data layer). A charting library for finance and occupancy (one-hue BarList molecule is enough and keeps the bundle small). Storing IVA-on-top pricing (the seeded invoices and the value model are consumer prices; a tax.pricesIncludeIva switch keeps both possible). A cross-tab storage listener in MockProvider (shared file; requested from the coordinator).
