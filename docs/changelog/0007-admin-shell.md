Below 900 px the same column becomes an off-canvas drawer with a scrim, opened from the top bar, and always shows full labels. A new `TopBar` composition (the organism gained `leading`, `code` and `center` slots; the existing `title`/`brand`/`back` behaviour is untouched for PhoneShell and P-*) carries the sidebar toggle, the wordmark, the page name from `bi(spec.name)` with the spec code as a chip, a `GlobalSearch` molecule in the middle (routes by name and code + members by name from `profiles`, `/` to focus, ↑↓, Enter navigates) and, on the right, ES/EN, theme, a `NotificationBell` molecule counting the current user's unread `message_log` rows, `RoleSwitcher`, the dev-mode toggle and the spec chip (`openInspector()`), degrading in that order as the viewport narrows. Feature switches moved to M-08: M-08 is now a family of five routed sub-pages behind one sub-navigation — M-08a General (`/admin/settings`), M-08b Features (`/admin/settings/features`, studio switches + the per-page `feature_flags` editor with the same audited writes and the same A-06/E-04 locks), M-08c Payments (`/admin/settings/payments`: payout account, NIT, IVA and DIAN, Wompi environment), M-08d Communications (`/admin/settings/communications`: quiet hours + sender names), M-08e Branding (`/admin/settings/branding`: display name, wordmark variant, default language, preview) — and `tenants.settings` gained `payments`, `comms` and `branding` sections, defaulted from `src/tenant/tenant.ts` and merged by `mergeSettings` like every other section. Wompi private keys are not a field: the page states they live in server environment variables and are never stored. The freed dashboard space became "Today at a glance" (today's sessions with occupancy, teacher, who is already checked in). `usePolicy()` is exported from `src/modules/admin/settings.ts` and re-renders consumers on every M-08 save because it reads `tenants` through `useTable()`. The design system reaches the admin through nav metadata only: the dev routes gained `group: core.nav.group.design` plus `nav.to` (a new optional field on `RouteDef.nav`) so the layout-editor entry opens `/dev/layout/C-01`, and `DesktopShell` appends the dev surface to the staff/admin sidebars when `isSuperAdmin`; the dev surface keeps its own shell and lists the admin group beside the design-system group. Containment is CSS only: flex and grid children get `min-width: 0`, prose and inline text get `overflow-wrap: anywhere` so codes, emails and IDs break instead of escaping, `pre`/media/tables are capped at 100 %, and the D-01 token rows, the D-02 library grid and the card heads/titles/values shrink instead of pushing.
rejected: (1) Keeping the feature switches on the M-01 dashboard (or mirroring them in both places) — the dashboard is read-at-a-glance and the switches are configuration with audited writes; two entry points would also mean two permission checks and two places to keep in sync. The dashboard keeps a link and the audit trail instead. (2) A second, separate "settings" sidebar group with five top-level nav entries — it would push the admin group past ten items and bury the daily pages; the sub-navigation keeps one "Ajustes" entry that stays active on all five routes. (3) One flat settings page with anchor links (today's rail) — it already scrolled past four screens, and Payments/Branding need their own URL to be linkable from the manual and from M-09. (4) A separate `AdminTopBar` component — the existing `TopBar` already renders in PhoneShell and P-*; adding three slots kept one organism, one CSS file and one meta instead of two barely different bars. (5) A CSS-only sidebar collapse (`:has()` + a checkbox) — state has to survive navigation and be remembered per surface, and the rail needs `aria-expanded` and tooltips, so React state + localStorage it is. (6) Copying the dev routes into the admin module to make the design system reachable — that would duplicate route definitions and their specs; nav metadata plus one surface rule in the shell keeps `src/modules/dev/index.ts` the only definition. (7) Storing the Wompi private key in `tenants.settings` behind a "secret" flag — the mock provider is localStorage, so a "secret" field would be a plaintext key in the browser; the page says so instead. (8) `word-break: break-all` for the containment pass — it breaks ordinary Spanish prose mid-word; `overflow-wrap: anywhere` only breaks when the word would otherwise overflow, and unlike `break-word` it also reduces the intrinsic minimum size, which is what lets a flex item shrink.
