# Partner activity reporting — test only
`GET /v1/reports/activity?from=YYYY-MM-DD&to=YYYY-MM-DD` serves up to 31 inclusive Bogotá days. The report carries approved purchase date, amount (COP) and an allowlisted product slug, plus daily signup, booking and attendance counts. It exposes no identities, internal payment references, checkout codes, notes, or class names. Payments use the recorded approval date and current approved status; pending transfers, holds, and voids are not purchases. Bookings and attendance are assigned by class date. This is reporting, not Meta CAPI or Wompi.

## Rollout boundaries
- Hard-disabled outside the existing passphrase-gated `test` environment. No gate bypass is added. After Company OS is verified on HOY test, enable only using **Deploy web (test)** from the approved annotated release tag with `partner-report=true`. An ordinary test deploy remains disabled; the partner opt-in refuses any ref without exact-commit Cut release evidence.
- Test setup needs a reviewed Company OS version with `GET /t/:tenantSlug/reporting/signup-counts`, an internal read-only identity scoped to the report's fields and the `reporting.signup_counts.read` capability, an independently expiring test-only client key, and a confirmed first day of reliable signup-history coverage. Do not reuse the public-site credential. In the GitHub **test** environment only, use secrets `HOY_PARTNER_TEST_KEY` and `HOY_PARTNER_TEST_UPSTREAM_KEY`, and variables `HOY_PARTNER_TEST_HISTORY_FROM`, `HOY_PARTNER_TEST_EXPIRES_AT` (future, no more than 24 hours away) and `HOY_PARTNER_TEST_PRODUCTS` (JSON for synthetic products). Use a verified synthetic-only tenant and do not copy credentials into logs or chat. Never grant external access to Company OS or the audit trail.
- Reconcile synthetic approved transfer, desk sale, hold, void, booked/no-show/check-in, staff-created profile and completed self-signup against aggregate totals. Verify wrong scope, wrong tenant, revoked upstream identity, expired client key, malformed dates, denied relation, oversize and timeout, plus absence in production. In a test tenant, verify the specific role's field projection—including optional product nulls—and compare totals with a trusted source. Current paginated reads are not transactionally consistent; live use would need a snapshot or defined closed-window policy. A live launch and any sparse purchase-data decision are separate.
- Cleanup/rollback: revoke the Company OS test identity (it does not expire automatically), turn the reporting flag off via the normal test deployment, remove the temporary test secrets and inputs from GitHub and Railway, and verify the endpoint is no longer available. No existing payments/bookings or Meta settings change.
