# AD-02 · Feature Log 88 · source row 89

Literal criterion: “When a class with sign-ups is cancelled, everyone is emailed and their class is returned.” This batch repairs the direct-paid return clause only. Email previews already exist; actual sending is not implemented. Recipient/preference handling and supported voucher-party cancellation remain explicit acceptance limits.

Native single/trial checkout saves an approved payment and a booking with `payment_id` and no ledger debit. The previous studio command required a debit for every attendee and therefore blocked the whole cancellation. Its older `single` fixture had a synthetic debit and did not represent that native topology.

The new direct-paid branch requires exactly one globally identified approved payment owned by the booking's tenant/customer, a valid immutable launch receipt, a matching class quote with quantity one/classes one, and a finite stored expiry. No current catalog price or expiry is consulted. Missing/ambiguous/foreign references, competing active uses, existing grants, malformed terms and unsupported quantities fail closed. Ordinary bookings represent one person each. Voucher bookings keep their explicit guard; companions are never reduced or omitted.

Studio cancellation atomically cancels every verified regular attendee, releases occupancy and inserts one deterministic positive returned lot for each direct-paid booking. That lot retains the payment/plan, frozen quote and exact recorded expiry. It creates neither a fabricated historical debit nor another payment or bank refund. A discriminated receipt item binds booking, original receipt/quote and returned-row digests. Existing ledger-backed receipt items are unchanged. Customer readback recognizes the returned lot, and the actual `bookWithPackage` command can use it; later consumption does not reissue a unit when the cancellation is replayed.

`node scripts/test-studio-cancel-direct-paid.mjs` exercises 39 synthetic actual-provider groups, including single/trial/mixed package attendees, a usable returned class, staged-write/quota rollback, after-start replay, exact origin/return corruption and actor context changes. Privileged cancellation/replay also requires the current scoped persisted admin role (or actual super-admin view-as); forged, missing, malformed, duplicate or lost privileges fail closed before mutation. `node scripts/test-studio-cancel.mjs` preserves the existing 15 groups. These are domain checks, not native browser or full application build proof. Source review, integrated build/browser checks and release are separate gates. No provider/schema, authentication, gift, email sender or permission contract changes.
