# Drawer keyboard dismissal

The original listener lived on the dialog node. If a focused action disappeared and focus returned to the document body, Escape and the existing outside-focus Tab guard no longer received that key event. The shared component now keeps one document bubble listener only while drawers are open. A private layer registry uses React ancestry across portals to choose the latest active innermost drawer, including initial nested mounting. Since the existing portal roots share a stacking value, the active leaf root is ordered after the other Drawer roots so pointer hit testing agrees with keyboard ownership. Reordering keeps the same body container, restores a focused descendant when needed, and leaves later unrelated portal siblings in place. Descendant keyboard events already consumed with preventDefault or stopPropagation retain their behavior.

Closing remains caller-controlled through the latest onClose callback. One key event is consumed once even when a nested callback synchronously unmounts its drawer. Original body overflow is restored after the last layer closes; nested parent-first unmount preserves the original external focus-return target. No payment controller, props, styles or tokens change.

The isolated harness uses the actual Drawer under React StrictMode. A normal button action replaces the focused control with a disabled keyed control, naturally moving focus to BODY; there is no forced callback invocation. It also checks ordinary dismissal, callback changes without refocusing, consumed Escape, Tab/Shift+Tab after lost/outside focus, nested dismissal, initial nested effects with actual pointer hit/click checks, all-layer unmount, repeated reopen and visible Close/overlay. EN/ES 390/1280 and dark cases use existing styles and localized Close labels.

The dedicated entry imports only existing component, theme and i18n dependencies. No application data or real services are involved.
