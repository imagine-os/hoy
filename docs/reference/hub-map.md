# Hub map — `hoy.hub-map/1`

One machine-readable map of everything HoyOS has, by role and by device, so that other hosts can
each draw the hoy hub through their own lens: the **aluzina** studio OS (hoy is an aluzina client — one
mat per client role), Justin's **between-gigs** company OS (hoy as one gig with its surfaces and
tools) and hoy's own **standalone** testing hub at `/#/`. **Checked 2026-09-29, v0.11.0 (0027).**

- **Published at** `https://imagine-os.github.io/hoy/hub-map.json` (source `public/hub-map.json`, committed).
- **Generated by** `npm run hub-map` (`scripts/gen-hub-map.mjs`), which also runs first in every `npm run build`,
  so the deployed file is always the deployed app.
- **One source of truth**: the hand-written half is `src/hub/hubMap.data.ts` — the same module HUB-01
  (`src/modules/hub/HubPage.tsx`) draws its bands and tool row from, and derives its card strings from. The
  route half (pages, roles per route, status, actions, names, purposes) is read from the live route registry
  through Vite's SSR loader — no browser, no parsed TypeScript, no stale copy.
- **Contract** (pure types): `src/hub/hubMap.types.ts`, reproduced below. A breaking change ships as
  `hoy.hub-map/2`; adding an optional field does not.

## Contract

```ts
export type Bi = { es: string; en: string };
/** How a host should draw the page: phone = app screen 390x844; tablet 768x1024; desktop 1280x800; page = a tall scrolling website page (390 wide, full length); sheet = a document/markdown page (docs, manual). */
export type HubDevice = 'phone' | 'tablet' | 'desktop' | 'page' | 'sheet';
export type HubBand = 'outside' | 'team' | 'build';
export type HubLensId = 'aluzina' | 'between-gigs' | 'standalone';
export type ThumbKey = 'es-phone' | 'en-phone' | 'es-desktop' | 'en-desktop' | 'es-phone-dark' | 'en-phone-dark' | 'es-desktop-dark' | 'en-desktop-dark';
export type ShotKey = 'es-390' | 'en-390' | 'es-1280' | 'en-1280' | 'es-390-full' | 'en-390-full';
/** URLs relative to `product.baseUrl`. A key is present only when the file is published. */
export interface HubShots { thumbs: Partial<Record<ThumbKey, string>>; full: Partial<Record<ShotKey, string>>; }
export interface HubRole {
  /** hoy Role id: customer | public | teacher | front_desk | coordinator | finance | admin | super_admin | maintenance */
  id: string;
  label: Bi; description: Bi;
  /** outside = customers/public/teachers, team = staff/admin, build = docs/dev */
  band: HubBand;
  /** ROLE_HOME route */
  home: string;
  /** The role's primary device. */
  device: HubDevice;
  demoUser?: { id: string; firstName: string };
  /** Figure look hint for hosts: 'customer' | 'teacher' | 'frontdesk' | 'coordinator' | 'finance' | 'admin' | 'superadmin' | 'public' | 'maintenance' */
  look: string;
  /** Two desk props from this vocabulary: laptop phone clipboard tape contract calculator plans ruler sketchbook pencils samples swatches board stamp hardhat tablet book keys mug rating */
  props: [string, string];
}
/** One per hub card (the 13 HUB_SURFACES) — the thing a role "enters". */
export interface HubExperience {
  id: string; code: string; label: Bi; purpose: Bi;
  /** Owning role (mat) + every role allowed in. */
  roleId: string; roles: string[];
  /** `url` = baseUrl + '#' + route */
  band: HubBand; device: HubDevice; route: string; url: string;
  featured?: boolean; secondary?: { label: Bi; route: string };
  /** Every page code inside this experience, in nav order. */
  pageCodes: string[];
  /** Of the experience's entry page. */
  shots: HubShots;
}
/** Every route that has a code (one entry per code; `route` is the code's first route). */
export interface HubPage {
  code: string; route: string; name: Bi; purpose: Bi; surface: string; roles: string[];
  experienceId: string; device: HubDevice; status: 'built' | 'stub'; actions: string[]; shots: HubShots;
}
export interface HubTool { id: string; code: string; label: Bi; purpose: Bi; route: string; url: string; device: 'desktop'; shots: HubShots; }
export interface HubLensHint { title: Bi; framing: Bi; groupBy: 'role' | 'experience' | 'surface'; showTools: boolean; entry: string; }
export interface HubMap {
  schema: 'hoy.hub-map/1'; generatedAt: string;
  product: { id: 'hoy'; name: Bi; tagline: Bi; version: string; baseUrl: string; hubRoute: string; brand: { accent: string; wordmark?: string } };
  /** pattern: '{baseUrl}#{route}?as={role}&lang={lang}&theme={theme}&dev=0&live=0' — exactly what src/app/frameSession.ts frameUrl() produces; hosts substitute and iframe it. */
  embed: { pattern: string; note: Bi };
  roles: HubRole[]; experiences: HubExperience[]; pages: HubPage[]; tools: HubTool[];
  lenses: Record<HubLensId, HubLensHint>;
}
```

| `lenses` | 3 | `aluzina` (groupBy role, no tools), `between-gigs` (groupBy experience, tools), `standalone` (groupBy surface, tools); `entry` is `/` for all three. |

### Page → experience

By surface, then by route prefix: `customer` → app (includes `/auth/*` and the E-01…E-04 states) ·
`teacher` → teacher · `staff` → inbox (`/staff/inbox*`), pos (`/staff/register`), else desk · `admin` → crm
(`/admin/crm*`), finance (`/admin/finance*`), else admin · `dev` → kb (`/dev/knowledgebase`), else dev ·
`docs` → manual (`/manual*`), else docs · `public` → site (`/site*`), dev (`/`, the hub itself), app
(`/no-access`, E-05). Every page belongs to exactly one experience and a page's `device` is its
experience's. Tool pages keep their experience too (D-01…D-06 sit in `dev`, M-03 in `admin`, K-04 in
`manual`, K-02 in `docs`); `tools[].code` points at the same page, so a host can draw it either way.
`pageCodes` are in nav order (routes with a `nav.order` first, the rest in registry order).

### Shots

Every URL is relative to `product.baseUrl` and lives under `hub-map/shots/<CODE>/` (`/` in a code becomes
`_`, as `thumbFolder()` does). A key is present only when the file is published:

| Key | File | Size |
| --- | --- | --- |
| `thumbs.<lang>-desktop[-dark]` | `thumb-<lang>-desktop[-dark].jpg` | 640 × 400 (a 1280 × 800 viewport at 0.5) |
| `thumbs.<lang>-phone[-dark]` | `thumb-<lang>-phone[-dark].jpg` | 195 × 422 (390 × 844 at 0.5) — customer, teacher and `/auth` pages |
| `full.<lang>-390` | `<lang>-390.jpg` | 390 × 844 viewport |
| `full.<lang>-1280` | `<lang>-1280.jpg` | 1280 wide, full page |
| `full.<lang>-390-full` | `<lang>-390-full.jpg` | 390 wide, full page, capped at 6000 px — the website's W-xx pages only (`npm run screenshots -- --full`) |

D-05 (canvas) and D-06 (simulator) have no thumbs, only the full captures. `scripts/copy-shots.mjs` copies
exactly the files the map names into `dist/`; if they ever exceed 80 MB the generator keeps thumbs for
every code and full captures only for the experience and tool entry pages (0027: 854 files, 61.6 MB, nothing trimmed).

## Embed recipe

`embed.pattern` is `{baseUrl}#{route}?as={role}&lang={lang}&theme={theme}&dev=0&live=0` — exactly what
`frameUrl()` in `src/app/frameSession.ts` builds for the hub's own previews.

1. `{baseUrl}` = `product.baseUrl`; `{route}` = an experience's or page's `route` (a `:id` segment is a
   template — replace it with a real id, or show the capture instead); `{role}` = a `roles[].id`;
   `{lang}` = `es` | `en`; `{theme}` = `light` | `dark`.
2. Load it in an `<iframe>` sized to the device (phone 390 × 844, tablet 768 × 1024, desktop 1280 × 800; `page` 390
   wide and scrolling; `sheet` like desktop) and scale it down with a CSS transform.
3. Inside the frame the app runs as that role's demo user: `installFrameSession()` shadows the session,
   language and theme keys for that document only and swallows writes, so the viewer's own hoy session is
   untouched. `live=0` stops nested previews; `dev=0` keeps dev tooling off.
4. **Same origin**: hoy and aluzina are both served from `imagine-os.github.io`, so a host there can also
   script the frame (`frame.contentWindow.__hoyos.run('hub.setLang', { lang: 'en' })`, read
   `__hoyos.routes`) and shares that origin's `localStorage` (every hoy key is `hoyos.*`, so nothing collides).
   From another origin the frame still runs as the role — the shadowing happens inside the frame — but the
   host cannot script it; draw faces from the shots and open the embed on click.

## Consumer checklist (for a host)

1. `fetch('https://imagine-os.github.io/hoy/hub-map.json')` (or bundle a snapshot of `public/hub-map.json`)
   and check `schema === 'hoy.hub-map/1'`; ignore unknown fields.
2. Read your lens: `lenses[<your id>]` gives the title, the framing sentence, `groupBy` and `showTools`.
   - `role` (aluzina): one mat per `roles[]` entry; on it, the experiences whose `roleId` is that role
     (and the role's `home` when it owns none); `look` and `props` dress the figure and the desk.
   - `experience` (between-gigs): one surface per `experiences[]`, its `pageCodes` resolved against `pages[]`.
   - `surface` (standalone): the three `band`s (outside · team · build), as hoy's own hub does.
3. Draw faces from `shots`: pick by `device` (phone → `thumbs.<lang>-phone`, else `-desktop`; `page` →
   `full.<lang>-390-full` when present), fall back to the other language, then to any key.
4. On enter, iframe the embed pattern **as the owning role** (`roleId`), or link to `url` for a full tab.
5. Texts are `{ es, en }`; Spanish is the product's default.
6. Re-fetch on a new `product.version`; `generatedAt` is the date of the changelog entry that produced it.

**Resumen (ES).** `hub-map.json` (esquema `hoy.hub-map/1`) describe todo hoy por rol y por dispositivo:
9 roles, 13 experiencias (las tarjetas del hub), 87 páginas, 9 herramientas y tres lentes (aluzina por rol,
between-gigs por experiencia, standalone por superficie). Lo genera `npm run hub-map` en cada build desde
`src/hub/hubMap.data.ts` (el mismo módulo que dibuja HUB-01) y el registro de rutas; las capturas se publican
en `hub-map/shots/`. Para incrustar una pantalla: `{baseUrl}#{route}?as={role}&lang={lang}&theme={theme}&dev=0&live=0` en un iframe.
