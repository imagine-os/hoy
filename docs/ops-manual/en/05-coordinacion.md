# Coordination

Your hub is **M-02 Content (CMS)**: classes, teachers, schedule, pricing and content, all with ES/EN fields and a draft → review → published flow.

## 1. Building the schedule
1. Fixed rule: 4 classes a day, 15 mats, one class per person per day. Spread the four movements (Enraíza, Fluye, Arde, Libera) across the day so "How do you want to feel today?" always has an answer.
2. Create the class as recurring in **M-02 → Schedule** (class type, teacher, room, time, recurrence). It appears in C-02, S-02 and S-03 on publish.
3. Always publish in Spanish; English falls back to Spanish when missing.
4. Schedule changes with at least 7 days notice; policy changes never affect bookings already made.
**Steps in HoyOS:** M-02 → Schedule tab → New recurring class → Publish. Verify in C-02 Class schedule (day and week views).

## 2. Teacher scheduling
1. Each teacher has availability on their profile (M-02 → Teachers). Assign without overlapping the same teacher's classes.
2. Substitutions: confirm the change in M-02 → Schedule the day it is agreed; the student sees the right name in C-02 and C-18.
3. Attendance outside the window (after T+2 h): you edit it in S-03 with a reason.

## 3. Cancelling a studio class
1. M-02 → Schedule → occurrence → Cancel (reason). The system returns credits, sends WhatsApp and email immediately (ignores quiet hours) and proposes same-day alternatives (E-03).
2. Tell the owner in the internal group. It counts against nobody.
**Steps in HoyOS:** M-02 Schedule → Cancel occurrence → confirm. Check delivery in M-05 → Log.

## 4. Events and workshops
1. Created as events with their own price, capacity and guest rule (C-23). Espacio prices (workshops, private sessions, photo/video, shoots, pop-ups) are "from" prices and end in a WhatsApp conversation, not a checkout.
2. An event does not replace the day's 4 classes unless the owner approves.
**Steps in HoyOS:** M-02 → Content → Event → publish; see C-23 Event detail & RSVP.

## 5. WhatsApp and email automations
1. **M-05 WhatsApp automations**: booking confirmed, reminder T−2 h, class cancelled, waitlist released, birthday, receipt, membership expiring, ask for feedback, invite. Each template needs Meta approval per language; a template in review leaves the automation off.
2. Quiet hours 9pm–7am: non-urgent waits until morning; cancellation and waitlist go through anyway.
3. **M-04 Transactional emails**: edit, preview in ES/EN, send yourself a test; the receipt carries the DIAN electronic invoice reference.
**Steps in HoyOS:** M-05 → automation list → editor → Meta status. M-04 → template → Send a test → Version history.

## 6. Content in the CMS
1. Class descriptions, teacher profiles, club rules (C-13), FAQ (C-14/C-15) and prices (P-01) live in M-02. Nothing is written twice.
2. What a teacher submits from S-03 enters review; approve or return with a comment within the week.
3. Photos are flagged as placeholders until real assets land.
4. Price changes: finance proposes, the owner approves, you apply them in M-02 → Pricing. They never affect active subscriptions.
